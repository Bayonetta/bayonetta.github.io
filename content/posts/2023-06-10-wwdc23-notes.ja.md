## Swift 5.9のmacro

macroにはfreestandingとattachedがある。`@freestanding`は`#stringify`のような式や宣言を生成し、`@attached`はmember、accessor、peer、attribute、conformanceなどを追加する。実装は`swift-syntax`を使った独立したcompiler-plugin targetに置き、`#externalMacro`から参照する。

```swift
@freestanding(expression)
public macro stringify<T>(_ value: T) -> (T, String) =
    #externalMacro(module: "MyMacros", type: "StringifyMacro")

let (value, text) = #stringify(1 + 2)
```

`Codable`のmember、accessor、protocol conformanceの生成など、boilerplateには向いている。一方でplugin targetが増え、`swift-syntax`のversionを厳密に合わせる必要があり、debugでは展開後のコードを見ることになる。小規模チームなら、数行を省くためのコストが大きいこともある。

## 短い構文と実験的な所有権

Optional bindingは`if let name`と書ける。この省略はSwift 5.9より前から存在する。Swift 5.9では`if`と`switch`を式として使い、値を直接生成できる。分岐は網羅的で、結果の型も一致しなければならない。

noncopyable typeはSwift 5.9で実験的に導入された。構文や所有権、ジェネリックとの関係はその後も変化していたので、当時は理解するだけに留め、productionへは入れなかった。

## SwiftDataとCore Data

SwiftDataは`@Model`でモデルclassを定義し、`ModelContainer`で保存を管理し、SwiftUIのviewでは`@Query`を使う。Core Dataはmigration、性能調整、debugの蓄積がある成熟したobject graph frameworkだ。

新規で単純なモデルを使い、SwiftUI中心でDeployment Targetを上げられるならSwiftDataは始めやすい。複雑なCore Data stack、手動migration、細かいfetched results controller、古いOSへの対応があるなら、急いで移行する理由はない。二つのmigration pathは同じではない。

## Observationと`@Observable`

Observationは、viewが実際に読んだプロパティを追跡する。旧来の`ObservableObject`では可変プロパティごとに`@Published`が必要だったが、`@Observable`ではmacroが追跡コードを生成し、`@StateObject`を`@State`へ変える構成も取れる。

新しい仕組みにはDeployment Targetの制約があり、`objectWillChange`やCombine購読をそのまま移せるわけではない。同じview treeでは一つの方式にそろえたほうが、更新問題を調べやすい。

## その他の更新

`#Preview`はcompile-timeの宣言としてpreviewを書ける。`ContentUnavailableView`は空状態を標準化する。`scrollTargetLayout`と`scrollTargetBehavior`は整列したpagingを簡単にする。TipKitには`Tip`、`TipView`、`popoverTip`がある。MapKitはcamera、annotation、styleをより宣言的に扱える。visionOSは新しいSDKと空間コンピューティングのtargetをもたらした。

## すぐ移行するもの

| 機能 | 判断 | 理由 |
| --- | --- | --- |
| `#Preview` | すぐ | previewだけに影響し、戻しやすい |
| Optional bindingと`if`/`switch`式 | すぐ | 局所的でコンパイラが守る |
| `@Observable` | 新規moduleはすぐ、既存は選択的に | deploymentとモデル境界の制約 |
| TipKitと新しいMapKit API | 必要に応じて | 対応OSと機能要件次第 |
| SwiftData | 待つ | Core Dataとmigration pathが同じではない |
| 自作macro | 待つ | pluginと`swift-syntax`の維持コスト |
| noncopyable | 待つ | 実験的な段階だった |

構文変更、preview変更、Observation移行は別コミットに分ける。データ層やDeployment Targetを触る前に、既存の回帰テストを通しておく。
