今回の最も大きな変化は、並行性の正しさがruntimeの約束からcompile-timeの制約になったことだ。これまではcode reviewと運に頼っていたdata raceを、コンパイラが止めるようになった。古いprojectほど移行量は大きい。正確な名前とavailabilityは公式ドキュメントを基準にする。

## Swift 6 language modeとstrict concurrency

Swift 6 language modeでは、多くの並行性ルールが必須になる。complete strict concurrency checkingを有効にすると、data raceの可能性がコンパイルエラーになる。中心にあるのはisolation domainだ。`actor`と`@MainActor`は特定の実行コンテキストに状態を閉じ込め、境界を越える値には`Sendable`が必要になる。

`nonisolated`は意図的な例外を示し、`sending`は元の場所でその値を使わなくなる場合の移動を表す。値型、不変データ、内部状態を保護した参照型が境界を越える値として安全で、自由に変更できる参照型は拒否される。

移行の順番は少し逆説的だ。まずSwift 5 modeで並行性warningをゼロにし、その後でlanguage modeを切り替える。

```swift
struct Counter: Sendable {
    var value = 0
}

@MainActor
final class ViewModel {
    private var value = 0
    func bump() { value += 1 }
}
```

可能なら値の意味へ変える。UIとview modelには`@MainActor`を付け、`nonisolated`は理由を書いた例外に限定し、`@unchecked Sendable`はlockや単一queueなどの不変条件を説明できる場合だけ使う。

## Swift TestingとXCTest

Swift Testingは`@Test`と式macroでテストを宣言する。`XCTestCase`を継承したり、メソッド名を`test`で始めたりする必要はない。

```swift
import Testing

@Test("偶数", arguments: [0, 2, 4, 6, 8])
func even(_ n: Int) {
    #expect(n % 2 == 0)
}

@Test func parseInt() throws {
    let value = try #require(Int("42"))
    #expect(value == 42)
}
```

`arguments:`は一つの宣言を複数のcaseへ展開し、`#require`はOptionalのunwrapに失敗した時点でそのcaseを止める。`@Suite`とtraitsで整理・絞り込みができる。新しいテストだけSwift Testingへ移し、既存のXCTestと同じtargetに共存させてもよい。

## XcodeとSwiftUIの更新

Xcode 16では`#Preview`の中で`@Previewable`を使い、previewのstateを直接宣言できる。SwiftUIには`MeshGradient`、scroll transition、UIKitとの相互運用の改善もある。ただし、いずれもDeployment Targetに依存するため、採用は製品の対応OSに合わせる。

## Apple IntelligenceとApp Intents

WWDC24ではApple Intelligenceが発表された。第三者アプリがすぐ使える接点はApp Intentsで、構造化されたentityとactionを公開し、Siri、Shortcuts、Spotlightなどから呼び出せるようにすることだった。第三者が端末上のfoundation modelへ一般的にアクセスできるframeworkはWWDC24の時点では提供されず、その流れは後のリリースに属する。

## 移行計画

| 手順 | 操作 | 受け入れ条件 |
| --- | --- | --- |
| 1 | Swift 5 modeのままstrict concurrencyを有効化 | 並行性warningがない |
| 2 | `Sendable`を追加し、可能なら値型へ変更 | 根拠のない`@unchecked Sendable`がない |
| 3 | UIとview modelの境界に`@MainActor`を付ける | main actor関連の型エラーがない |
| 4 | `nonisolated`の例外を確認 | すべて理由が書かれている |
| 5 | 一度に一つのtargetだけSwift 6へ移す | unit/UI testが通る |
| 6 | unchecked annotationと並行性回帰テストを見直す | 説明できない逃げ道がない |

移行を戻せる状態に保つルールは二つ。language modeを変える前にwarningをゼロにし、一度に一つのtargetだけを切り替える。WWDC24で最も手がかかるのは、提案から標準へ移った`Sendable`、`@MainActor`、actor isolationだ。
