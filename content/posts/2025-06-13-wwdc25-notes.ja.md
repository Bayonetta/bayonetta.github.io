WWDC25を見て、実際に対応が必要になりそうなことが二つあると感じた。ひとつは、半透明で動的なマテリアルによって、カスタムコントロールのコントラストやタップ領域をもう一度確認する必要が出てきたこと。もうひとつは、Foundation Modelsによって、オンデバイス推論をアプリ側でスケジュールし、制約を付け、失敗時の代替経路まで用意できるようになったことだ。

## 日々の開発に影響しそうな三つの変更

まずはiOS 19の動的なマテリアルとコントロール。ツールバー、タブ、ナビゲーションバー、標準コントロールは、周囲の背景に合わせてより積極的に変化する。カスタムコントロールでは、セマンティックカラーを使い、主要情報と補助情報のコントラストを保ち、静止画だけでなく実機でも確認したい。操作領域は従来どおりおよそ44ポイントを目安にする。カスタム`UIView`なら、見た目の大きさを変えずに`point(inside:with:)`でタップ領域を広げられる。

次はFoundation Modelsフレームワークだ。`@Generable`と`@Guide`で構造化された結果を定義し、`LanguageModelSession`と`SystemLanguageModel`でセッションと利用可能性を扱う。JSON文字列を受け取って再度パースするのではなく、Swiftの値として結果を受け取れる。

```swift
import FoundationModels

@Generable
struct BookRecommendation {
    @Guide(description: "書名。かぎ括弧は付けない")
    var title: String
    @Guide(description: "一文で書いた推薦理由")
    var reason: String
    @Guide(description: "1から5までの推薦度")
    var rating: Int
}

func recommend(for query: String) async throws -> BookRecommendation {
    let session = LanguageModelSession(
        instructions: "あなたは慎重な技術書の推薦アシスタントです。"
    )
    let response = try await session.respond(
        to: query,
        generating: BookRecommendation.self
    )
    return response.content
}
```

`Tool`プロトコルを使えば、ツール呼び出しも定義できる。各ツールに名前、説明、スキーマを与え、非同期の`execute`を実装してセッションに渡す。ただし、モデルの回答が正しいことを保証するものではない。`Guide`が制約するのは結果の形であって、内容の真偽ではない。

このフレームワークにも制約はある。多くのサーバーモデルよりコンテキストが小さく、初回起動、遅延、ストリーミング、対応デバイス、オフライン時の利用可能性を考える必要がある。`SystemLanguageModel.default.availability`を確認し、タイムアウトを設け、テンプレート、クラウドサービス、機能無効化などの代替手段を用意したい。throwing task groupを使えば、生成処理とタイムアウトを競わせ、負けたタスクをキャンセルできる。

三つ目は、Swift 6.2で並行処理を導入しやすくなったことだ。新しいモジュールでは`SWIFT_DEFAULT_ACTOR_ISOLATION`によるデフォルトの`MainActor`分離を選べる。処理を本当に並列で動かす必要がある場合に`@concurrent`を使い、`nonisolated`は意味を確認してから付けるようにしたい。

## App Intentsとコーディング支援

Spotlight、ショートカット、システムレベルのアクションに対応するなら、`AppIntent`、`AppEntity`、`EntityQuery`、`AppShortcutsProvider`が実用的な入口になる。アプリの外からも使う価値があるアクションやエンティティは、これらのAPIで記述してシステムにインデックスしてもらう。

Xcodeのコーディング支援は、雛形作成や繰り返し作業には便利だ。ただし、生成されたコードも必ずコンパイルし、レビューし、実際のアプリの動作まで追う必要がある。

## 慎重に導入する順番

| 項目 | 方針 |
| --- | --- |
| App IntentsとSpotlight | すぐ導入する |
| 利用可能性確認とタイムアウト付きの`@Generable` | すぐ導入する |
| 新しいSwift 6.2モジュールのデフォルト`MainActor`分離 | 様子を見て計測する |
| オンデバイスでの事実生成 | 様子を見て、信頼できる情報源で検証する |
| カスタムマテリアルの全面的な再設計 | 実機検証が終わるまで保留する |
| クラウド推論の全面置き換え | 能力と遅延のデータがそろうまで保留する |

WWDC25から得た実用的な教訓は、どこにでもモデルを追加することではない。結果の形を決め、利用可能性を確認し、タイムアウトを設定し、モデルなしでも動く経路を残すことだ。
