## Swift 5.9 的宏体系

宏的角色分两类。`@freestanding` 生成独立的表达式或声明（写作 `#stringify` 这种形式）；`@attached` 附着到声明上，追加成员、访问器、peer 声明或扩展。常见的附着角色有 `@attached(member)`、`@attached(accessor)`、`@attached(peer)`、`@attached(memberAttribute)`，以及带一致性声明的扩展角色。具体角色名和参数以官方文档为准。

实现侧依赖 `swift-syntax`。展开逻辑放在独立的编译器插件 target 里，声明侧用 `#externalMacro` 指向插件类型。宏代码不在 App 进程里跑，编译期由编译器调用，展开的产物照样做类型检查。

```swift
// 宏声明：位于独立的宏库 target
@freestanding(expression)
public macro stringify<T>(_ value: T) -> (T, String) =
    #externalMacro(module: "MyMacros", type: "StringifyMacro")

// 使用侧：编译器展开宏，并对展开结果做类型检查
let (value, text) = #stringify(1 + 2)
```

宏真正解决的痛点是样板：自动写 `Codable` 成员、生成访问器、补协议一致性。代价也实在——多一个插件 target，和 `swift-syntax` 的版本严格对齐，调试时看到的是展开后的代码。团队规模不大的话，为省几行样板引入这套东西不太划算。

## 更短的写法

可选绑定可以省掉右侧的同名赋值，写作 `if let x`。这个简写是 Swift 5.7 就有的，别记成 5.9 新增。

Swift 5.9 新增的是 `if` / `switch` 直接当表达式产生值，省掉「先声明变量、再逐分支赋值」那一步。

```swift
// 可选绑定简写
if let name {
    print(name)
}

// Swift 5.9：if / switch 作为表达式
let label = if score >= 90 { "优秀" } else { "继续" }

// 假设 status 只有三种情况
let symbol = switch status {
    case .idle: "—"
    case .running: "▶"
    case .done: "✓"
}
```

分支必须穷尽、产出类型一致，否则编译器直接拒绝。这条改起来很安全，适合逐文件小步替换。

## noncopyable 还只是实验形态

Swift 5.9 首次以实验形态引入不可复制类型。当时拼写带下划线前缀，要开实验特性，语义也不完整。`~Copyable` 的写法、抑制默认复制的规则、它跟泛型和所有权提案的关系，都是后面几个版本才逐步定型的。

这届的态度很简单：读得懂提案就行，别往生产代码里放。

## SwiftData 与 Core Data

SwiftData 用 `@Model` 描述模型类，`ModelContainer` 管存储栈，`@Query` 在视图里取数据，整套写法是跟 SwiftUI 对齐的声明式风格。Core Data 则是成熟的图与对象图管理框架，迁移、性能调优、调试工具都有多年积累。

```swift
import SwiftData

@Model
class Note {
    var title: String
    var createdAt: Date
    init(title: String, createdAt: Date = .now) {
        self.title = title
        self.createdAt = createdAt
    }
}
```

选择上，全新项目、模型简单、以 SwiftUI 为主、部署目标能抬到新系统的，用 SwiftData 起步更快。已经有复杂 Core Data 栈、依赖手动迁移、用着细粒度 fetched results controller、或者要跨旧系统版本运行的，没必要换。

两者的迁移路径不等价，混用要谨慎。

## Observation 与 `@Observable`

视图只跟踪它实际读到的属性——这是 Observation 带来的最大变化。

旧写法要给每个可变属性标 `@Published`，没标就漏更新，标多了又无关刷新。`@Observable` 把跟踪交给编译期展开的代码，属性不用逐个标注，持有容器从 `@StateObject` 换成 `@State`。

```swift
import SwiftUI
import Observation

// 旧写法：ObservableObject + @Published
final class LegacyCounter: ObservableObject {
    @Published var count = 0
    @Published var title = "Counter"
}

struct LegacyView: View {
    @StateObject private var model = LegacyCounter()
    var body: some View {
        VStack {
            Text(model.title)
            Text("\(model.count)")
            Button("+1") { model.count += 1 }
        }
    }
}

// 新写法：Observation 框架的 @Observable
@Observable
class Counter {
    var count = 0
    var title = "Counter"   // 未被读取的属性不会触发视图更新
}

struct CounterView: View {
    @State private var model = Counter()
    var body: some View {
        VStack {
            Text(model.title)
            Text("\(model.count)")
            Button("+1") { model.count += 1 }
        }
    }
}
```

`@Observable` 需要新的部署目标，`ObservableObject` 那套 `objectWillChange` 和 Combine 订阅搬不过来。两套模型能在同一个工程里并存，但一个视图树内最好只用一种，否则排查刷新问题时会被绕晕。跟 `@Environment`、`@Bindable` 配合的用法以官方文档为准。

## 其余更新

`#Preview` 把预览写成编译期可检查的声明，比 `PreviewProvider` 轻，一个文件里放多组状态也方便。`ContentUnavailableView` 补上了空状态和搜索无结果的标准呈现。`scrollTargetLayout` 配合 `scrollTargetBehavior`，分页对齐不用自己算偏移量了。TipKit 提供 `Tip` 协议和 `TipView`、`popoverTip` 等入口做新手提示。MapKit 把地图内容改成更声明式的写法，相机位置、标记与地图样式有了统一入口。

```swift
import SwiftUI

struct GalleryView: View {
    var body: some View {
        ScrollView(.horizontal) {
            LazyHStack {
                ForEach(0..<20, id: \.self) { index in
                    RoundedRectangle(cornerRadius: 12)
                        .fill(.teal)
                        .frame(width: 160, height: 200)
                        .overlay(Text("\(index)"))
                }
            }
            .scrollTargetLayout()
        }
        .scrollTargetBehavior(.viewAligned)
    }
}

#Preview("画廊") {
    GalleryView()
}

#Preview("空状态") {
    ContentUnavailableView(
        "没有结果",
        systemImage: "magnifyingglass",
        description: Text("换个关键词再试一次")
    )
}
```

visionOS 带来了新的 SDK 和空间计算场景。Xcode 15 把 Swift 5.9 工具链、宏支持、`#Preview` 以及对应模拟器、构建流程一起交付。CI 镜像、最低部署目标和插件 target 的依赖都得跟着调。

## 什么该马上迁移

| 项目 | 判断 | 理由 |
| --- | --- | --- |
| `#Preview` 宏 | 立即 | 只影响预览代码，不改运行时行为，替换与回滚成本都低 |
| 可选绑定简写与 `if` / `switch` 表达式 | 立即 | 局部语法，编译器兜底，适合逐文件小步替换 |
| Observation 的 `@Observable` | 新模块立即，旧模块择机 | 受最低部署目标约束，与 `ObservableObject` 混用要划清边界 |
| TipKit、MapKit 新入口 | 按需 | 取决于产品支持的系统版本与是否真的需要该功能 |
| SwiftData | 等 | 与 Core Data 的迁移路径不等价，已有复杂数据栈不必急 |
| 自研宏 | 等 | 需独立插件 target 与 `swift-syntax` 版本对齐，团队成本高于收益 |
| noncopyable | 等 | 早期实验形态，拼写与语义仍在演进 |

真动手时按提交拆：语法替换、预览宏改造、Observation 切换各自独立成一次提交，别跟 SwiftData 或部署目标调整混在一起。动数据层之前，先把旧实现的回归测试跑通。
