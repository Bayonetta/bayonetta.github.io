The most important change this year is that concurrency correctness moved from a runtime convention to a compile-time constraint. Data races used to rely on code review and luck; the compiler now blocks many of them. The migration cost is real, especially in older projects. Exact names and availability belong to the official documentation.

## Swift 6 language mode and strict concurrency

Swift 6 language mode makes more concurrency rules mandatory. With complete strict concurrency checking, data races become compiler errors. The central idea is isolation domains: `actor` and `@MainActor` protect state for a specific execution context, and values crossing the boundary must be `Sendable`.

`nonisolated` marks an intentional exception. `sending` allows a value to be transferred when the original location will no longer use it. Value types, immutable data, and reference types with protected state are the safest boundary values; freely mutable references are rejected.

The migration order is counterintuitive: first make Swift 5 mode's concurrency warnings reach zero, then switch the language mode.

```swift
struct Counter: Sendable {
    var value = 0
}

@MainActor
final class ViewModel {
    private var value = 0
    func bump() { value += 1 }
}
```

Prefer value semantics when possible. Use `@MainActor` for UI and view models, reserve `nonisolated` for documented exceptions, and treat `@unchecked Sendable` as an escape hatch that requires an invariant—such as a lock or a single queue—to be written down.

## Swift Testing and XCTest

Swift Testing uses `@Test` and expression macros instead of requiring `XCTestCase` inheritance or method names beginning with `test`.

```swift
import Testing

@Test("even numbers", arguments: [0, 2, 4, 6, 8])
func even(_ n: Int) {
    #expect(n % 2 == 0)
}

@Test func parseInt() throws {
    let value = try #require(Int("42"))
    #expect(value == 42)
}
```

`arguments:` expands one declaration into several cases, and `#require` stops the current case when an optional cannot be unwrapped. `@Suite` and traits organize and filter tests. New tests can use Swift Testing while existing XCTest tests remain in the same target.

## Xcode and SwiftUI updates

Xcode 16 lets `#Preview` declare preview state directly with `@Previewable`. SwiftUI also gains `MeshGradient`, scroll transitions, and smoother UIKit interoperability. These features are deployment-target dependent, so adoption should follow the product baseline.

## Apple Intelligence and App Intents

WWDC24 introduced Apple Intelligence. For third-party apps, the immediately actionable integration point was App Intents: expose structured entities and actions so Siri, Shortcuts, Spotlight, and other system entry points can invoke them. General-purpose third-party access to an on-device foundation-model framework did not arrive at WWDC24; that timeline belongs to later releases.

## A migration plan

| Step | Action | Acceptance condition |
| --- | --- | --- |
| 1 | Keep Swift 5 mode and enable complete strict concurrency checking | No concurrency warnings |
| 2 | Add `Sendable`; convert to value semantics where possible | No unjustified `@unchecked Sendable` |
| 3 | Mark UI and view-model boundaries `@MainActor` | Main-actor calls type-check |
| 4 | Review every `nonisolated` exception | Each has a written reason |
| 5 | Move one target to Swift 6 language mode | Its unit and UI tests pass |
| 6 | Revisit unchecked annotations and add concurrency regression tests | No unexplained escape hatches |

The two rules that keep the migration reversible are simple: clear warnings before changing language mode, and switch one target at a time. The expensive part of WWDC24 is concurrency—`Sendable`, `@MainActor`, and actor isolation became defaults rather than suggestions.
