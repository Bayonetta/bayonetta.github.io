这届最要紧的变化只有一个：并发正确性从运行时的约定，变成了编译期的约束。

以前数据竞争靠 code review 和运气，现在编译器会拦。代价是迁移量不小，尤其是有年头的老工程。API 名称、可用版本与具体签名一律以官方文档为准。

## Swift 6 language mode 与严格并发

Swift 6 language mode 把一批此前可选的并发规则升级成默认，配合 complete strict concurrency checking，让数据竞争在编译期就报错。

核心概念是隔离域。`actor` 和 `@MainActor` 各圈出一块只能被特定执行上下文访问的状态，跨域传递的值必须满足 `Sendable`。`nonisolated` 声明某个成员不参与隔离，属于少数例外；`sending` 表示值交给对方之后原处不再使用，让编译器放行一部分本来会被判越界的传递。

值类型、不可变数据、内部状态受保护的引用类型才适合跨边界传递，裸的可变引用类型会被拦下。`sending`、`nonisolated` 的确切语义和拼写在整个 Swift 6 周期里还在演进，以官方文档为准。

## 一段在 Swift 6 下报错的代码

下面这段在 Swift 5 mode 下只是警告，切到 Swift 6 language mode 直接编译失败：

```swift
import Foundation

// 非 Sendable 的可变引用类型
final class Counter {
    var value = 0
}

@MainActor
func bump(_ counter: Counter) {
    counter.value += 1
}

func callFromBackground() async {
    let counter = Counter()
    // Swift 6 language mode：counter 在 await 之后还要用，
    // 编译器无法把它整个送进隔离域，报 sending risks causing data races
    await bump(counter)
    print(counter.value)
}
```

报错落在 `await bump(counter)` 这次调用上。注意这里的关键不是「传了非 `Sendable` 的引用」，而是「传完之后原处还要用它」。Swift 6 的区域隔离分析（SE-0414）允许把只此一份的值直接送过去，所以把最后那行 `print` 去掉，同一段代码就合法了。这条边界比想象中窄，也是迁移时最容易被误判的地方。

所以迁移顺序是反的：先在 Swift 5 mode 下把警告清零，再切模式。

修正有两条路：

```swift
// 修正一：改成值语义，让类型满足 Sendable
struct Counter: Sendable {
    var value: Int
}

// 修正二：把状态整体隔离，不再把引用带出隔离域
@MainActor
final class ViewModel {
    private var value = 0
    func bump() { value += 1 }
}
```

优先第一条，它顺手把共享可变状态也消掉了。两条都不需要 `@unchecked Sendable`。

## 遗留代码的标注顺序

我给自己的顺序是：先给跨边界传递的值类型补 `Sendable`（能改成值语义就改），再给 UI 层和视图模型标 `@MainActor`，然后处理少数 `nonisolated` 例外并逐条写下理由，最后才考虑 `@unchecked Sendable`。

`@unchecked Sendable` 等于让编译器跳过检查。内部状态一旦真的会被并发改写，数据竞争就回到运行时，连警告都没有。每一处都得配注释，说明不变量由什么机制保证——内部锁、只在单一队列访问，诸如此类。`nonisolated(unsafe)` 同理，可用版本和限制以官方文档为准。

## Swift Testing 与 XCTest

Swift Testing 用宏声明测试，用表达式宏做断言，不再要求继承 `XCTestCase`，也不要求方法名以 `test` 开头。

```swift
import Testing

@Test("偶数判定", arguments: [0, 2, 4, 6, 8])
func even(_ n: Int) {
    #expect(n % 2 == 0)
}

@Test func parseInt() throws {
    let value = try #require(Int("42"))
    #expect(value == 42)
    #expect(value > 0)
}
```

`@Test` 的 `arguments:` 把一组输入摊成多个用例，失败时能定位到具体参数。`#require` 解包失败时抛出并终止当前用例。`@Suite` 和标签 traits 用来组织和筛选。

| 维度 | Swift Testing | XCTest |
| --- | --- | --- |
| 声明方式 | `@Test` 宏，函数名自由 | 继承 `XCTestCase`，方法名以 `test` 开头 |
| 断言 | `#expect`、`#require`，失败信息带表达式 | `XCTAssert` 系列 |
| 参数化 | `arguments:` 直接传集合 | 需自行循环或借第三方封装 |
| 组织 | `@Suite` 与标签 traits | 靠测试类分组 |
| 异步 | 原生 `async` 测试 | 常需 `XCTestExpectation` |

新写的单测直接用 Swift Testing。既有的 XCTest 不必重写，两个框架能在同一个 target 共存。具体宏签名与 trait 名称以官方文档为准。

## Xcode 16 的预览与补全

Xcode 16 允许在 `#Preview` 宏内部直接声明状态变量，省掉为预览额外包一层容器的样板：

```swift
#Preview {
    @Previewable @State var isOn = true
    Toggle("开关", isOn: $isOn)
}
```

预测式代码补全结合当前工程的类型与上下文给建议，属于本地工具链能力，不进运行时代码。

## SwiftUI 的几处更新

`MeshGradient` 用网格点控制颜色分布，适合背景和非规则渐变；滚动过渡让列表项随滚动位置改变外观；UIKit 互操作增强让 SwiftUI 里嵌 `UIViewRepresentable` 一类的桥接更顺手。

```swift
import SwiftUI

let points: [SIMD2<Float>] = [
    SIMD2<Float>(0, 0), SIMD2<Float>(0.5, 0), SIMD2<Float>(1, 0),
    SIMD2<Float>(0, 0.5), SIMD2<Float>(0.5, 0.5), SIMD2<Float>(1, 0.5),
    SIMD2<Float>(0, 1), SIMD2<Float>(0.5, 1), SIMD2<Float>(1, 1)
]

struct Backdrop: View {
    var body: some View {
        MeshGradient(
            width: 3,
            height: 3,
            points: points,
            colors: [.teal, .blue, .indigo, .mint, .white, .purple, .cyan, .blue, .black]
        )
    }
}
```

这几项都受最低系统版本约束，按需采用。初始化参数、滚动过渡与互操作 API 的具体名称以官方文档为准。

## Apple Intelligence 与 App Intents

WWDC24 首发了 Apple Intelligence。对第三方开发者来说，当时真正能落地的接入点主要是 App Intents：把 App 的能力以结构化意图暴露给系统，让 Siri、快捷指令、聚焦这些入口能调。

这里有个容易记错的时间线：面向第三方 App 的设备端大模型能力，并没有在 WWDC24 就以通用 framework 的形式开放，Foundation Models framework 是 2025 年的事。所以那一年该做的是把 App Intents 的结构化意图做扎实——实体、参数、短语、错误处理。

## 迁移步骤

按模块逐步开 Swift 6：

| 步骤 | 动作 | 验收条件 |
| --- | --- | --- |
| 1 | 保持 Swift 5 mode，打开 complete strict concurrency checking，把警告清零 | 构建无并发相关警告 |
| 2 | 给跨隔离域传递的类型补 `Sendable`，能改值语义就改 | 类型检查通过，且不引入 `@unchecked Sendable` |
| 3 | 给 UI 层与视图模型标 `@MainActor`，明确隔离边界 | 主线程相关调用不再报错 |
| 4 | 枚举 `nonisolated` 例外，逐条写明理由 | 例外数量可枚举、有注释 |
| 5 | 一次只把一个 target 切到 Swift 6 language mode | 该 target 单测与 UI 测试全绿 |
| 6 | 复核并清理 `@unchecked Sendable`，补并发回归测试 | 无无理由的 unchecked 标注 |

关键是第 1 步和第 5 步：警告清零再切模式，一次只切一个 target。这两条守住了，迁移就是个可回退的工程问题，而不是一次赌博。

这届真正费工夫的是并发：`Sendable`、`@MainActor`、`actor` 隔离，从建议变成了默认要求。session 编号、具体签名与部署要求以官方文档为准。
